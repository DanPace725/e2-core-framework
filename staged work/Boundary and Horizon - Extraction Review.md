## Working Read

The boundary material is currently trying to do several jobs at once:

1. define what boundaries are,
2. describe how boundaries operate,
3. describe what boundaries generate for observers,
4. describe how boundaries become layered or stratified,
5. measure boundary and substrate condition,
6. evaluate failure modes,
7. guide interventions.

That mixture is productive during synthesis, but it will become hard to maintain if it stays in one document. The clean move is to create useful boundaries around the boundary concepts themselves.

## Existing Boundary Dynamics

`Boundary Dynamics` already has a strong and coherent scope.

It defines boundaries as:

- relational, not edge-like,
- active, not passive,
- observer-relative,
- recursive,
- temporal,
- typed by state and capacity,
- composed through nesting, layering, and coupling,
- governed by mode-wise and component-wise conservation,
- bounded by threshold behavior,
- prone to typed failure modes.

Its strongest role:

```text
Boundary Dynamics = structural/operator theory of inter-regional engagement.
```

It answers:

```text
What is the structural object through which regions engage?
How does that object operate?
What modes, capacities, thresholds, and failure modes does it exhibit?
```

## New Boundary/Horizon Material

The staged documents add several distinct layers.

### 1. Horizon As Epistemic Access-Limit

The new material distinguishes:

```text
boundary = structural differentiation that permits form and regulates engagement
horizon  = access-limit produced by that form from an observer position
```

This is not a replacement for Boundary Dynamics. It is an epistemic companion.

Boundary Dynamics explains what the boundary is doing. Horizon language explains what the boundary makes visible, invisible, reachable, unreachable, legible, or misrecognized from a position.

### 2. Resolution, Remainder, Occlusion

The five-term system is stable enough to extract:

| Term | Function |
| --- | --- |
| resolution | accepts loss to stabilize coherence |
| boundary | cut/operator that permits form |
| horizon | access-limit produced by form |
| remainder | what exceeds present access |
| occlusion | mistaking the horizon for the whole |

This connects naturally to MMPS, Signal as Bias Field, and AOMI.

### 3. Redshifted Remainder

The staged documents name a useful mechanism:

```text
redshifted remainder = real signal beyond the current horizon that is attenuated
below recognition by observer position, bias-field curvature, compression,
noise, or receiver tuning.
```

This should be treated as candidate-formal SBF/AOMI language, not as established math yet.

### 4. Layers And Conditions

Boundary Dynamics already has nesting, layering, and coupling.

The new material adds:

- boundary layers as generated contact regions,
- stratified zones inside boundary surfaces,
- local interface films,
- bound collective substrate,
- transition conditions from local film to substrate,
- surfactant structures that stabilize non-merging contact,
- observer-position headers for measurement.

These additions should not all live in the same boundary source document.

### 5. Boundary Universality Guardrail

The new material usefully softens the strongest cross-domain claim.

Safe claim:

```text
bounded systems exhibit recurrent relational patterns:
selectivity, permeability, recursion, load response, failure modes,
horizon generation, and threshold behavior.
```

Unsafe claim:

```text
all boundaries obey identical equations across all substrates.
```

This guardrail should be incorporated into future revisions because it protects the framework from overextending physical analogies into agentic domains.

## Merge, Extend, Or Split?

Recommended action: **split first, then extend selectively**.

Do not merge all new boundary/horizon material directly into `Boundary Dynamics`.

Reason:

`Boundary Dynamics` is already doing a specific job: structural/operator theory. The new material adds epistemology, measurement protocol, interface ontology, practice implications, and research guardrails. Merging everything would make the document broader but less usable.

Best architecture:

| Document | Role |
| --- | --- |
| `Boundary Dynamics` | structural/operator theory |
| `Boundary and Horizon` | epistemic/access theory |
| `Boundary Conditions and Layers` | stratification, threshold conditions, layering, interface films |
| `Boundary Measurement Protocol` | observer headers, proxy families, evaluation routines |
| `Interface Substrate Ontology` | local interface film to bound substrate |

Only after these are clean should `Boundary Dynamics` receive a short extension note and cross-links.
