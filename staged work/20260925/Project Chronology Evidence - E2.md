## Method and limits

H4 in `Outbound Release Process v0.2.md` asks whether outward practices precede or run alongside the corpus's articulation, and proposes dating artifacts against corpus documents. This appendix records dated project evidence, while preserving the distinction between project activity and project conception. The repository checkout at review time has an empty `.git` directory; `git log` cannot supply commit IDs or commit dates. Filesystem last-write times were not used as origin evidence because many are migration/build/dependency artifacts and their provenance is unclear. Earliest dated surviving artifact means only “activity evidenced by this date,” never “project began then.” Where source text gives no reliable date, the date is **unknown**. “Active evidence” below describes the observed dated interval, not continuous work.

## Interpretation boundary

This record supports comparisons only where an outward-practice artifact or event is actually dated. In particular, it does not establish that a project started on the date of its oldest surviving file, that file-system timestamps equal authorship dates, or that a dated software run represents an external receiver event. Git chronology is unavailable in this checkout. Keep retrospective user reports, external events, authored documents, and technical run records distinguishable when using this appendix to assess H4.
